# Codex 実装報告: 日本限定・半径検索ランキング・流星群SEO

作成日: 2026-08-16

対象ブランチ: `agent/stars-japan-radius-seo`

対象: `stars/` の公開フロントエンドと検証コード

## 1. 依頼と結論

次の4点を実装した。

1. 地図の「表示の設定 > 濃さ」を撤去した。表示濃度は従来の既定値に固定する。
2. 地図操作と地点指定を日本周辺の範囲に制限し、世界地図の複製描画を止めた。
3. 「流星群 観測スポット」を探す利用者向けに、タイトル、説明、H1、内部リンクの文言を改善した。
4. 一覧の「地図にピンを打って近い順」を、中心と半径10〜100kmを指定し、範囲内を今夜の星見レベル順にランキング表示する方式へ変更した。

Supabase のスキーマ・データ・関数には変更も書き込みも行っていない。掲載スポットも追加・削除していない。

## 2. 実装内容

### 2.1 濃淡設定の撤去

- `stars/index.html`: 「表示の設定」と濃さスライダーを削除。
- `stars/app.js`: スライダーのイベント処理を削除。
- `stars/map.js`: 外部公開していた `setOpacity` を削除。ラスタは既定の不透明度で描画する。
- `stars/stars.css`: 削除した設定UI専用のスタイルを削除。

### 2.2 日本以外を対象外にする処理

- `stars/config.js`: 地図の操作範囲を `[[122, 20], [154, 46]]` に定義。
- `stars/map.js` / `stars/pick.js`: `maxBounds` を適用し、`renderWorldCopies: false` を設定。
- `stars/list.js` / `stars/pick.js`: 範囲外の中心座標を検索条件として受理しない。

この制限は日本の島しょ部を含む矩形であり、厳密な行政界ポリゴンではない。地図の端には構図上必要な近隣国・海域が一部見えるが、国外へ移動し続けたり世界を反復描画したりできない。天気格子・光害データ・地名索引・掲載スポットは従来から日本向けのデータだけを使っている。

### 2.3 流星群観測スポット向けSEO

対象検索意図は「日本国内で、今夜または流星群の夜に行ける観測スポットを近くから探したい」とした。

- `stars/index.html`: title、meta description、OG title/description、H1を更新。
- `stars/list.html`: title、meta description、OG title/description、H1、導入文を更新。
- トップページから一覧への内部リンクを「流星群・星空の観測スポットを探す」に変更。

検索語を並べるだけではなく、実際に提供する機能（日本、現在地・地名・地図、半径10〜100km、天気・月・光害、ランキング）と説明を一致させた。

### 2.4 半径内ランキング

- 中心の指定方法は「地名・住所」「現在地」「地図」の3通りを維持。
- 検索半径は10〜100km、10km刻み。初期値は50km。
- ハーサイン距離による既存の直線距離計算を使い、半径外を一覧から除外。
- 中心指定後の既定並びは「今夜の星見レベル順」。旧「近い順」は削除。
- 検索結果の各行に `1位`、`2位` の順位と中心からの直線距離を表示。
- 0件時は、半径を広げるよう案内。
- 地図側は球面計算で64分割の円ポリゴンを作り、塗りと輪郭を表示。半径変更時は円と表示範囲を更新する。
- 検索条件を解除した場合は円を空にし、通常の全件一覧へ戻す。

なお、ランキングは距離順ではない。利用者が観測先を選ぶ目的に合わせ、指定範囲内で「今夜の星見レベル」が高い順とした。距離は各行に併記する。

`scripts/stars/verify.mjs` に次を追加・変更した。

- 流星群向け title / description / H1。
- 濃淡スライダーが存在しないこと。
- 地図の最大範囲が日本周辺であること。
- 半径スライダーが10〜100km・10km刻みであること。
- 旧「近い順」が残っていないこと。

`scripts/stars/verify_live.mjs` に、公開後もSEO、半径設定、濃淡設定の不在、日本範囲制限を確認する項目を追加した。

## 6. 公開手順と継続ルール

この変更は次の順番でのみ公開する。

1. 作業ブランチをpush。
2. `main` 宛てPRを作成。
3. PRの差分・検証結果を確認して `main` へマージ。
4. マージ済みの `main` を `gh-pages` へ反映。
5. GitHub Pagesのビルド完了後、公開URLを再検証。

今後も、公開サイトを直接先行変更せず、必ずPRで `main` に反映してから `gh-pages` を更新する。
