# B. 掲載の枠が変わった ── 先に結論を出してください

**当初の4条件は「無料・予約不要・他人に迷惑をかけない・安全」でした。**
これは候補を選ぶ**ふるい**で、条件を満たさないものは候補から外していました。

今回、Hiroさんは条件を満たさないものを**採用**しました。

|---|---|---|---|
| 44 | 香川県 大川山キャンプ場 | 有料・利用許可制・12/1〜3/31休業 | 大川山キャンプ場を有料施設として紹介すればよい |
| 46 | 和歌山県 みさと天文台 | 夜間観望は全員事前予約制 | 公式のツアーを勧める |
| 16 | 兵庫県 砥峰高原駐車場 | 駐車料金500円 | 砥峰高原駐車場に変更。駐車料金５００円 |

つまり掲載するものが2種類になります。

1. **4条件を満たすもの**（思い立った日に、無料で、予約なしで行ける）
2. **満たさないが、そのことを明記して載せるもの**（有料・要予約・時間制限）

**利用者にとってはまったく別物です。** 「今夜どこへ行けば星が見えるか」を見に来た人が、
予約制の天文台ツアーを「今夜行ける場所」だと思って出かけたら、それは案内の失敗です。

## B-1. いまのデータには、これを表す場所がありません

`stars_spots` の列は
`name / name_kana / pref / city / lat / lon / elevation_m / access / facilities / note / caution / source_url`
だけです。**有料か・予約が要るかを持つ列はありません。**
候補JSON（`spot-candidates.json`）には `free` と `resv` がありますが、
これは選別のためのもので、サイトへは渡していません。

## B-2. 決めてほしいこと

次のどれで行くか、**根拠つきで1つ勧めてください**（実装はそのあと）。

1. **列を足す**。`stars_spots` に `is_free` / `needs_reservation` のような列を持たせ、
   一覧と詳細に印を出す。絞り込みもできる。
   → スキーマ変更が要る（`setup.sql` と差分SQL、`migrate.test.sh` の同値比較も）
2. **`caution` に書くだけ**にする。列は増やさない。
   → 楽だが、一覧では見えない。詳細を開かない人には伝わらない
3. **別枠にする**。4条件を満たすものだけを一覧に出し、
   有料・要予約のものは「予約して行く場所」として別の並びにする
   → いちばん誤解が少ないが、画面が増える

**私（Claude）の見立て**: 1が妥当だと考えます。一覧は「今夜行ける場所」を探す画面なので、
有料・要予約が一覧の時点で見えないと選び間違えます。ただし列を足すのは
本番スキーマの変更なので、Hiroさんの承認が要ります。**あなたの判断を聞かせてください。**

## B-3. 文言も見直しが要ります

`stars/about.html` と `stars/list.html` は「無料・予約不要」を前提にした書き方になっています。
枠が変わるなら、そこも合わせてください。
