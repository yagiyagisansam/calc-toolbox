## P1-1 iframeをセキュリティ境界として扱わない

現状の `sandbox="allow-scripts allow-same-origin"` は、同一生成元の子が親DOMへ直接アクセスできるため、子侵害時の隔離にならない。コメントと設計資料から「閉じ込めた」「親に届かない」と読める表現を除く。

優先実装:

1. 地図文書を別originで配信できる構成を検討する。
2. 親はその固定originだけを `frame-src` と受信元に許可する。
3. 子も固定した親originだけへ返信する。
4. 別origin化できない場合は、現在の分離を依存コード整理としてだけ位置付ける。

併せて `submit.js` の `pick`、`pick.js` の `init/mark` でlat/lon双方を `Number.isFinite` と物理範囲で検証する。`postMessage` のsource/origin検査は維持する。

## P1-2 「N時間続く」のoff-by-oneを直す

サンプル数を時間数として表示しない。`times[i+1] - times[i]` から区間長を求め、隣接区間として継続時間を計算する。予報刻みを1時間と仮定しない。

最低限のテスト:

- 合格1サンプルだけで「1時間続く」と表示しない。
- 1時間差の合格2サンプルは約1時間。
- 3時間刻みでも3時間として扱う。
- 欠測をまたいで連続扱いしない。
- 一覧と詳細が同じ値を出す。

共通関数へ寄せ、`GOOD_MIN=65` も重複定義しない。

## P1-3 集落索引のロード条件と検索条件を一致させる

- 300〜500ms debounce。
- 正規化後2文字未満ではロードしない。
- 主索引が0件のときだけ集落結果を混ぜる。ロード済みでもこの条件を変えない。
- 都道府県が選択済みなら県別データを取得する構成を優先する。
- 未選択時は「小さな地名も探す」明示操作を検討する。
- iPhone相当で転送量、parse時間、heap増分、入力応答を測る。

`places.test.mjs` に「集落索引ロード後、主索引が1件返る検索へ集落を足さない」を追加する。

## P1-4 地名補完をID・応答fixture・種別検証にする

国土地理院地名検索をビルド時だけ使い、`query / expectedTitle / expectedPref / expectedMuniCodes / expectedKind` を補完定義に保存する。完全一致・種別・逆ジオの全条件が通ったときだけ座標を採用し、生応答とSHA-256をfixture化する。

美ヶ原、洞爺湖、四国カルスト、野辺山は次をテストする。

- 入力名と同じ地形・地域が返る。
- 洞爺湖町を洞爺湖の代用にしない。
- 野辺山集落を野辺山高原と無表示で取り違えない。
- 複数候補ならビルド停止。

公式に安定ID付き機械可読データがない場合のみ、Wikidata QID等を補助元にし、revisionと応答hashを固定する。

## P1-5 日本語別名を捨てない

表示名と検索別名を分ける。GeoNames IDごとに日本語別名を `aliases` として保持し、どの別名でも同一地点へ到達させる。検索結果は地点IDで重複排除する。阿蘇山だけの個別上書きで終わらせない。
